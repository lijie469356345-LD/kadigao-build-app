账号注册 · 组织引导定位流程（方案 v2 · 确认版）

核心理念注册页不再展示完整组织树（859 节点），改用「职能范围 → 角色/区域 → 候选列表 → 组织层级」的引导式三问，最终归属组织由申请人自己选定、管理员审核时终审。

第 0 步 · 注册页前置字段（沿用现状）

  • 姓名 + 手机号（11 位校验）+ 仓库类别（下拉：直营 / 加盟 / 山东直营，系统已按 用户全 实际值提供）
  • 仓库类别 = 问题 1 的替代：它锁定后续门店类候选的过滤范围，无需再单独问"业务线"

门店命名带城市/县域前缀（洛阳、郑州、南阳、平舆、山东泰安、河南鲁山…），区域关键词可用 org_name LIKE '%区域%' 匹配；仓库类别过滤：直营 → L4/L6 门店，加盟 → L7 门店，山东直营 → 山东前缀门店。

两个关键实现约束

1）区经 / 督导节点名不含区域（"区经_许奕清"、"督导_陈会琴"），无法直接按名称匹配用户输入的区域。
处理：按区域关键词在其下辖门店名称中反查 — 命中门店 → 沿 ancestors 取对应区经 / 督导组节点 → 去重后作为候选；下拉联想词直接取自门店名前缀的 DISTINCT 集合，引导用户输入已有区域。
2）总监 / 专员节点分 直营 / 加盟 / 山东 变体（如"运营总监直营""运营总监加盟""运营总监山东"）。仓库类别已在前置字段选择，可作为预过滤；若用户所选仓库类别无对应变体（如"数据总监"只有一个），则全量展示该职能的候选，由用户在最后一步自行选择具体节点，不再追加问题。

兜底与审核衔接（沿用已上线的注册审核逻辑）

  • 多次无匹配退路：候选为空且用户选择「由管理员确认归属」时，org_id 允许为空提交；
  • 审核终审：注册审核页「通过」「补充资料」弹窗中，归属组织为必选项，管理员强制补选最终归属（该能力已实现）；
  • 数据链路不变：申请仍落 register_apply.org_id，审核通过创建用户时沿用并允许修改，补充字段全链路兼容。
