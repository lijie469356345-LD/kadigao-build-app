卡迪高巡店系统 - 独立运行版 部署说明
==================================================

一、本程序包含的功能（全功能，非精简）
- 登录 / 权限管理
- 巡店任务、巡店日志、日志未完成统计
- 微信推送（企微配置、模板、接收人、推送记录）
- 报表、对比报表、评分体系、店铺诊断
- 用户管理、店铺档案、维护模式
- 公众反馈、自动合并 / 在线合并、月度目标分解
- 数据库配置等原系统全部模块

二、数据库配置（页面输入驱动，不再写死，保存后永久生效）
- 程序不再硬编码任何数据库地址。启动后，在「数据库连接」页面输入什么就连接什么。
- 内置默认连接（仅作初始值，可改）：120.48.100.89,1433 / 库名 LDCS / 账号 ld / 密码 Ld940821
- 你可在「数据库连接」页面改成你自己的真实库（地址 / 端口 / 库名 / 账号 / 密码），
  点「测试连接」验证，再点「保存配置」——配置会写入 exe 同级目录的 config.json，
  重启程序后依然生效，不会再变回旧地址。

三、你需要做的事（只需做一次）
1. 在新服务器（用账号 ld / Ld940821）上新建一个数据库，
   名称与你打算在「数据库连接」页面填写的库名一致（默认 LDCS）。
   若你之后在页面改了库名，新库名按你填的来即可。
2. 把旧服务器 192.168.110.200 上「伯俊库」的全部表，复制到新库「LDCS」。
   完整表清单见随附的《表清单.txt》（共 109 张表，含 用户全、店仓全、
   InspectionTasks、StoreInspectionLogs、WechatPush* 等）。
   推荐用 SQL Server「生成脚本」或「导出数据」整体迁移，确保
   表结构 + 数据都过去（账号、店铺、任务、日志、推送配置都在里面）。
3. 确认新库 120.48.100.89 的 1433 端口，对运行 exe 的机器可达
   （若 exe 就跑在 120.48.100.89 本机，localhost 即可）。

四、启动
1. 把 CardigaoInspection.exe 拷到新服务器任意目录（如 D:\卡迪高巡店系统\）。
2. 双击 CardigaoInspection.exe：
   - 程序自动解包到临时目录并启动 Node 服务；
   - 约 5~8 秒后自动打开浏览器 http://localhost:3000 ；
   - 若未自动打开，手动访问 http://localhost:3000 。
3. 登录：使用原系统的账号密码（用户全表已随表一起复制过去，账号不变）。
4. 配置真实数据库（关键）：
   - 进入「数据库连接」页面，确认/修改 服务器地址、端口、库名、账号、密码；
   - 点「测试连接」验证（成功会提示"数据库连接成功"）；
   - 点「保存配置」——此后所有功能（任务/日志/推送）都按这个连接走，
     重启程序也不会变回旧地址。
   （若你直接沿用内置的 LDCS 默认连接且表已迁入，可跳过测试/保存，直接可用。）

五、企业微信可信域名验证文件（新增）
- 需求：让 `http://你的域名/WW_verify_xxxx.txt` 可访问（企业微信在后台添加可信域名时，
  会下载一个 `WW_verify_xxxx.txt` 要求放到域名根目录做校验）。
- 新版 exe 已内置该能力：程序会自动响应 `/WW_verify_xxxx.txt` 请求，
  返回的内容即文件名里的校验码（企业微信标准格式），无需你手动放文件。
- 同时，程序会在 80 端口额外监听一份（企业微信验证默认走 80 端口），
  与主服务（默认 3000）共用同一套路由。
  - 若 80 端口绑定成功（建议右键 exe「以管理员身份运行」），
    企业微信直接访问 `http://你的域名/WW_verify_xxxx.txt` 即可通过校验。
  - 若 80 被占用或无权限绑定失败，程序会提示"80 端口监听失败"，
    此时请用反向代理把 80 转发到 3000（如 Nginx: `location / { proxy_pass http://127.0.0.1:3000; }`），
    或让域名直接指向 3000（不推荐，需改端口）。
- 自定义覆盖：若企业微信给的文件内容不是纯校验码，可在 exe 同级目录建 `public\` 文件夹，
  把 `WW_verify_xxxx.txt` 放进去，程序会优先读取该文件（持久目录优先于内置内容）。

六、测试微信推送
1. 进入「巡店日志」→ 新建 / 编辑日志 → 提交。
2. 微信推送模块每 30 秒轮询待推送记录，自动发往企业微信。
3. 在「微信推送 → 推送记录」查看送达状态。
   注意：企微接收人需在「用户全」表中填正确的企微账号（企微 userid），
   否则会报"用户不存在"导致推送失败。

七、停止服务
关闭 CardigaoInspection.exe 所在的黑色命令行窗口，
或在任务管理器结束 CardigaoInspection.exe 进程即可。
（若之前因管理员运行而监听了 80 端口，关程序会一并释放 80。）

八、常见排错
- 提交日志 / 任务失败：先到「数据库连接」页面，确认地址、库名、账号、密码填的是
  你新服务器的真实信息，点「测试连接」能成功，并已「保存配置」。
- 连不上数据库：确认新库已建、表已导入、1433 端口通、账号有读写权限。
- 页面空白 / 样式错乱：浏览器强制刷新清缓存（Ctrl + F5）。
- 日志显示"数据库连接失败"：此时程序会用 Mock 数据运行、功能受限，
  需先按第三步把数据库准备好并在「数据库连接」页保存正确配置。

附：表清单见《表清单.txt》（共 109 张表）。

九、权限管理（GroupPermissions）数据说明（重要）
- 表结构：groupName（用户组）、supervisor（督导）、shopName（店铺），三者联合唯一。
- 写入规则（一店一条，不再交叉乘积）：
  在「权限管理」选好用户组、勾选店铺后保存，程序会为「每家被选店铺」生成 1 条记录，
  supervisor 列自动取「该店铺自身的督导」（从店仓全取 督导+区域 拼成 督导{区域}{姓名}，
  如 督导郑州刘小丽），不再需要手动勾选督导。
- 例：用户组=经理郑州，勾选 100 家店 → 生成 100 条记录，每条的 supervisor = 那家店自己的督导。
- 因此「管理组」全选所有店时，记录数 = 店铺数，不会因为督导多而翻倍。
- 若你之前手动 ALTER 加过 supervisor 列、但唯一约束还是旧的 UK_GroupNameShop，
  新程序保存时会自动规整为四列结构（含 UK_GroupNameSupervisorShop），无需你再手动处理。
